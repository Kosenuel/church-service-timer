# 0.18 — Stage communication, recovery and printing

1. **Royal Navy arc:** normal remaining time uses a green progress arc. The rest of the gold theme stays intact; warning remains amber and overtime red.
2. **Fixed print footer:** Print Service generates a paginated PDF through Android's print framework. Every page reserves footer space for “Church Service Timer · I-Proton” and “Page N of M”, with repeated table headings and no footer-only page.
3. **Church watermark:** a faint, bold, diagonal church name is checked by default. Turning it off is remembered. An empty church name produces no watermark. It does not replace the footer.
4. **Print presets:** Stage copy excludes private notes; choosing Operator copy enables notes, which can still be unchecked. The church banner remains checked initially. Ink-saving suppresses banner and watermark without clearing the saved watermark choice. Historical documents use recorded service data, with a separate preparation date/time and timezone.
5. **Warning expiry:** Settings → Warnings & alerts offers 15, 30 (default), 60 seconds or Until dismissed for phone warning notifications. A segment change or service end clears obsolete warnings. This setting does not shorten stage cues or remove the active-service foreground notification. Android controls actual notification presentation, sound and Do Not Disturb.
6. **Local drafts:** program edits and unsent Quick messages are debounced to local storage. Program drafts offer Restore, Discard or Cancel when reopened; Quick message drafts offer Restore/Discard. Restoring does not save the program or send the message. Storage failures retain pending edits for retry. Drafts are excluded from portable backups and paired snapshots. A process killed before its pending write completes can still lose the newest keystrokes.
7. **Deletion Undo:** deleting one prepared cue or automatic warning offers an eight-second Undo, restoring its full formatting. Report deletion retains its existing confirmation and is not covered by Undo.
8. **Targeted messages:** choose all connected stage screens, a saved screen, or General/Preacher/Choir/Media desk screens. Only selected, approved, synchronized stage receivers receive the message. The recipient set is fixed when Send is pressed; new or reconnected screens do not replay it. Other receivers keep their normal output. Post-service messages still require confirmation and never change the historical report.
9. **Seen acknowledgements:** optionally request Seen in the message composer or preset. Recipients explicitly tap Mark Seen. The host displays per-recipient status and a count. A transport acknowledgement is not Seen; old, replaced, expired or untargeted messages cannot be acknowledged. Seen does not grant operator control.
10. **Screen options:** each saved viewer/stage device has a group and a Timer only / Timer + current segment / Timer + next segment layout. These are stored in the local pairing vault. Messages temporarily replace that layout; private notes are never shown on stage. The host can select a particular acknowledged screen preview. Update receivers to 0.18 for the new layouts and Seen button.
11. **Recover time:** Live → service rundown → Recover time proposes reductions to upcoming segments. Protect important segments, review the before/after durations, then explicitly apply. The current/completed segments, saved program and previous reports remain unchanged; each remaining segment keeps at least one minute. A changed service or control state requires another review.
12. **Timing insights:** Reports → Timing insights uses up to five recent comparable services per program and requires at least three observations. It excludes rehearsals, incomplete/uncertain records, ambiguous segment names and paused time. Suggested durations use median active time, rounded up. Program editor → Learn from previous services applies only selected suggestions to the draft; Save is still required.

Both Matrix fonts and the W2 hardware serialization remain unchanged. Existing all-screen Quick messages continue to take priority over automatic stage cues; targeted Quick messages do not suppress warnings on other screens. No sign or phone UI tests are performed for this update at the user's request. Automated checks use local encrypted peer sessions and generated PDF fixtures; hands-on verification belongs to the user.

## Reproducing PDF review

Run `dart run scripts/print-preview.dart <output-directory>` from the repository after dependencies are installed. This generates long Operator, Stage and Ink-saving fixtures using the app's actual PDF generator and bundled fonts. Check every page's footer, repeated headings, separate service/preparation dates, note visibility and banner/watermark suppression. The older HTML helpers remain for compatibility; the app's Print Service flow uses `lib/service_pdf.dart`.
